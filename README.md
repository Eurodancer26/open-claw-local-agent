# 🤖 Open-Claw Local AI Orchestrator & Vibecoder UI

Автономный локальный AI-оркестратор с архитектурой «Plan & Execute» и встроенным веб-интерфейсом **Vibecoder UI**, оптимизированный для работы на потребительском железе (Intel Arc GPU, 8 GB VRAM) без облачных зависимостей.

---

## 📌 1. Концепция и цель проекта

Проект **Open-Claw Local AI Orchestrator** создан для решения ключевой проблемы локальных языковых моделей среднего размера (7B-8B параметров): склонности «уплывать» в рассуждения, путаться в многоступенчатых инструкциях и выдавать сырой неструктурированный код.

За счет строгой модульной архитектуры, разделения задач планирования и точечного исполнения, а также жесткого контроля контекста через `node-llama-cpp`, система превращает компактную модель (например, Qwen 2.5-7B Instruct) в надежный автономный инструмент разработки и анализа с удобным браузерным интерфейсом.

## 🏗️ 2. Архитектура и структура проекта

Проект построен по принципам чистой модульности (ESM) и четкого разделения зон ответственности:

```text
open-claw-local-agent/
├── public/                     # Статические файлы веб-интерфейса (Vibecoder UI)
│   └── index.html              # Интерактивная панель управления с поддержкой SSE
├── models/                     # Локальное хранилище GGUF-моделей (git-ignored)
│   └── qwen2.5-7b-instruct-q4_k_m.gguf
├── src/
│   ├── api/
│   │   └── routes.js           # Маршрутизатор Express и эндпоинты /v1/chat/completions
│   ├── core/
│   │   └── engine.js           # Синглтон-ядро инициализации llama.cpp и управления сессией
│   ├── tools/
│   │   └── registry.js         # Модульный реестр инструментов (writeFile, readFile, runCommand)
│   └── server.js               # Точка входа, запуск сервера и раздача статики
├── tests/
│   └── sandbox/                # Изолированная песочница для тестов (git-ignored)
├── benchmark.js                # Скрипт комплексного технического бенчмаркинга
├── benchmark-clean.js          # Скрипт проверки чистоты генерации кода
├── test.js                     # Набор интеграционных функциональных тестов
└── package.json                # Манифест зависимостей и скрипты
```

## ⚙️ 3. Ключевые технические решения

### 3.1. Управление памятью и VRAM (Singleton Pattern)
* **Проблема:** Повторная инициализация модели при каждом HTTP-запросе приводит к мгновенному исчерпанию видеопамяти (VRAM) на картах с 8 GB (Intel Arc A580) и падению процесса.
* **Решение:** Реализован паттерн Singleton в модуле `src/core/engine.js`. Модель загружается в память ровно один раз при старте сервера и удерживается в активной сессии с фиксированным окном контекста (`contextSize: 2048`) и полным оффлоадом слоев на GPU (`gpuLayers: 99`).

### 3.2. Пайплайн «Plan & Execute»
Обработка запроса пользователя разделена на независимые этапы:
1. **Фаза планирования:** Модель анализирует входящий запрос и строит четкий нумерованный план из логических шагов (2–4 шага).
2. **Фаза выполнения:** Каждый шаг по очереди передается в модель вместе с контекстом. Система активирует инструменты (Function Calling) через модульный реестр.

### 3.3. Цикл самопроверки (Self-Correction Loop)
Система перехватывает ошибки выполнения команд (`stderr` / `error` из `runCommand`) и автоматически передает их модели для исправления кода на лету через инструмент `writeFile`.

### 3.4. Веб-интерфейс Vibecoder UI
Интерфейс на базе Server-Sent Events (SSE) в реальном времени отображает ход планирования, статус шагов выполнения, вызовы инструментов и результаты работы агента прямо в браузере.

## 📊 4. Метрики производительности и бенчмарки

На аппаратной конфигурации:
* **CPU:** AMD Ryzen 5 3600
* **GPU:** Intel Arc A580 (8 GB VRAM)
* **Модель:** Qwen-2.5-7B-Instruct (Q4_K_M GGUF)

| Тип задачи / Тест | Количество шагов | Время выполнения (сервер) | Стабильность VRAM |
| :--- | :---: | :---: | :---: |
| Аналитический запрос (Сравнение ФП и ООП) | 3 шага | ~$5.4$ сек | Стабильно (~0 утечек) |
| Генерация кода (Скрипт чтения package.json) | 4 шага | ~$7.6$ сек | Стабильно |
| Генерация крипто-хеша (`crypto` модуль) | 2 шага | ~$6.9$ сек | Стабильно |
| Алгоритмическая задача (Функция палиндрома) | 3 шага | ~$8.2$ сек | Стабильно |

## 🚀 5. Быстрый старт и установка

1. **Клонирование репозитория и установка зависимостей:**
   ```bash
   git clone https://github.com/Eurodancer26/open-claw-local-agent.git
   cd open-claw-local-agent
   npm install
   ```

2. **Загрузка модели:** 
   Поместите файл модели `qwen2.5-7b-instruct-q4_k_m.gguf` в директорию `models/`.

3. **Запуск сервера:**
   ```bash
   node src/server.js
   ```

4. **Использование интерфейса:**
   Откройте браузер и перейдите по адресу:
   👉 **`http://localhost:3000`**

5. **Запуск тестов и бенчмарков (в отдельном окне терминала):**
   ```bash
   node test.js          # Функциональные тесты
   node benchmark.js     # Технический бенчмарк
   ```
