# Open-Claw Local Agent 🐾🤖

Профессиональный, безопасный и готовый к продакшену локальный AI-агент на базе **Node.js (ESM)** и **`node-llama-cpp`**, оптимизированный для работы с аппаратным ускорением на GPU (включая Intel Arc).

## 🚀 Основные особенности

* **Эффективное управление VRAM:** Архитектура синглтона для LLM-движка (`src/core/engine.js`) предотвращает дублирование моделей в памяти и перегрузку видеопамяти при обработке запросов.
* **Строгая безопасность (Sandbox):** Защита от *Directory Traversal* через валидацию путей (`resolveWorkspacePath`), блокировка симлинков и строгий белый список команд (`SAFE_COMMANDS`) для инструмента `runCommand`.
* **Гибкий API:** Поддержка как классических JSON-ответов (`stream: false`), так и потоковой передачи данных в реальном времени через SSE (`stream: true`).
* **Надежное тестирование:** Комплексный набор тестов на базе встроенного `node:test` (проверка песочницы, безопасности и сквозные интеграционные сценарии с реальной LLM).

---

## 🛠 Технологический стек

* **Runtime:** Node.js (ESM)
* **Web Framework:** Express.js
* **LLM Engine:** `node-llama-cpp` (интеграция с локальными GGUF-моделями, например, Qwen 2.5)
* **Тестирование:** `node:test`, `node:assert`

## 📦 Установка и запуск

1. **Клонируйте репозиторий и установите зависимости:**
   ```bash
   git clone https://github.com/your-username/open-claw-local-agent.git
   cd open-claw-local-agent
   npm install
   ```

2. **Подготовьте модель:**
   Поместите файл модели (например, `qwen2.5-7b-instruct-q4_k_m.gguf`) в директорию `models/` в корне проекта.

3. **Запуск сервера:**
   ```bash
   npm start
   ```
   Сервер будет доступен по адресу `http://localhost:3000`.

## 🧪 Тестирование

В проекте предусмотрено два уровня автоматического тестирования:

* **Быстрые тесты песочницы, API и безопасности (без загрузки LLM):**
  ```bash
  npm test
  ```

* **Полный набор тестов (включая сквозной HTTP-запрос к реальной локальной LLM на GPU):**
  ```bash
  npm run test:llm
  ```

## 🔒 Безопасность инструментов

Агент взаимодействует с файловой системой и окружением через изолированный реестр инструментов (`src/tools/registry.js`):
* `readFile` / `writeFile` — строгий контроль доступа исключительно внутри рабочей директории с проверкой симлинков.
* `runCommand` — выполнение только предварительно одобренных системных команд из белого списка (`git-status`, `node-version`, `run-test`).
