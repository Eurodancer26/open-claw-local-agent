# AI Construct (Open-Claw Local Agent)

**AI Construct (Open-Claw Local Agent)** — полностью автономный, приватный локальный AI-агент на базе **Node.js (ES Modules)** и **`node-llama-cpp`**, построенный по паттерну **Plan & Execute** с автоматической самокоррекцией (**Self-Correction**), рекурсивной нейро-маршрутизацией запросов на CPU, персистентной памятью размышлений и трассировкой выполнения в XML.

Проект создан для полностью локальной работы без обращения к внешним облачным API, с изоляцией файловых операций в песочнице, строгим контролем контекста и сериализацией обращений к видеопамяти через кастомный GPU-мьютекс (`gpuMutex`), что делает его устойчивым на системах с ограниченным объёмом VRAM (включая **Intel Arc A580, 8 ГБ VRAM**).

## Архитектурный пайплайн

Каждый запрос пользователя проходит через многоступенчатый локальный конвейер без отправки данных за пределы машины:

```text
[Пользователь / Web UI / HTTP Client]
                │
                ▼
      POST /v1/chat/completions
                │
                ├──► 1. Захват GPU-мьютекса (gpuMutex)
                ├──► 2. Санитайзинг и обрезка истории (contextPruner.js)
                ├──► 3. CPU Нейро-маршрутизация (NeuralSkillRouter)
                │        ├── Векторизация 7 признаков + фокус длинного промта
                │        ├── Рекурсивное скрытое состояние (hiddenState[8])
                │        └── Оценка векторов: chat | file_ops | system_cmd
                ├──► 4. Загрузка опыта и антипаттернов (recursiveMind.js)
                ├──► 5. Сборка когнитивного промпта (chatFormatter.js)
                ├──► 6. Инференс локальной GGUF-модели (node-llama-cpp)
                │
                ├─── [Текстовый ответ] ──► Запись в память и ответ в чат
                │
                └─── [JSON-план шагов]
                          │
                          ▼
               7. Парсинг и восстановление JSON (planParser.js)
                          │
                          ▼
               8. Цикл исполнения (executor.js)
                  ├── Проверка безопасности путей (pathSecurity.js)
                  ├── Выполнение инструмента (toolsRegistry)
                  ├── Защита от зацикливания (Loop Guard)
                  └── При ошибке ──► Самокоррекция (askModelToFixStep)
                          │
                          ▼
               9. Сохранение рефлексии (mind/) и XML-отчёта (reports/)
```

## Ключевые подсистемы

### 1. Рекурсивный нейро-роутер на CPU (`src/core/neuralRouter.js`)
Перед обращением к тяжёлой языковой модели запрос анализируется лёгкой рекурсивной нейросетью на чистом JavaScript (`NeuralSkillRouter`), работающей за доли миллисекунды на CPU:

* **Архитектура сети**: `7` входных вещественных признаков $\rightarrow$ `8` нейронов скрытого рекурсивного слоя (`tanh`) с матрицами $W_{xh}$, $W_{hh}$ и смещениями $B_h$ $\rightarrow$ `3` выходных логита (`chat`, `file_ops`, `system_cmd`) с нормализацией `softmax`.
* **Вектор входных признаков (`extractFeatures`)**:
  1. `isChatOrQuestion` — приветствия, вопросы, объяснения, сравнения, вопросительные конструкции.
  2. `hasFileAction` — глаголы и существительные файловых операций (`создать`, `записать`, `прочитать`, `удалить`, `модуль`, `папка` и т. д.).
  3. `hasPathOrExt` — относительные пути, слэши, расширения файлов (`.js`, `.ts`, `.json`, `.md`, `.css`, `.scss`, `.sql` и др.), каталоги проекта (`src/`, `tests/`, `mind/`, `models/`).
  4. `hasSystemCmd` — системные и CLI-маркеры (`node`, `npm`, `git`, `версия`, `запусти`, `терминал`, `скрипт`, `docker` и др.).
  5. `isShortReply` — короткие уточняющие реплики в ходе диалога (например, указание целевой папки после вопроса агента).
  6. `hasCodeOrSymbols` — фрагменты синтаксиса, ключевые слова JS/HTML, скобки, стрелочные функции.
  7. `hasAnalysisOrTest` — задачи на аудит структуры, статистику, рефакторинг и генерацию unit-тестов.
* **Работа с длинными и составными промтами**:
  * `extractPromptFocus` выделяет смысловое ядро длинного текста (начало и конец запроса), чтобы многословные описания не размывали целевое действие.
  * Флаг `isBroadOrMixed` сигнализирует модели, когда запрос затрагивает сразу несколько направлений.
  * При резкой смене темы (например, после файловых операций пользователь спрашивает версию `node` или задаёт общий вопрос) рекурсивная инерция `hiddenState` динамически ослабляется, предотвращая «залипание» прошлого контекста.
* **Дообучение и персистентность**: методы `trainStep`, `trainBatch`, `save()` и `load()` с валидацией размерностей матриц (`hasValidDimensions`) для сохранения весов в `models/neural_router_weights.json`.

### 2. Устойчивый парсер планов (`src/core/planParser.js`)
Локальные квантованные модели периодически оборачивают JSON в блоки Markdown, добавляют висячие запятые или оставляют неэкранированные кавычки внутри `description` и `content`. Модуль `safeParseJsonPayload` выполняет многоступенчатую очистку и восстановление JSON-структуры, а `extractActionPlan` извлекает нормализованный массив шагов.

### 3. Исполнитель планов и самокоррекция (`src/core/executor.js`)
* **Нормализация шагов (`normalizeStep`)**: поддерживает как вложенный объект `arguments` / `args`, так и плоскую передачу параметров (`filePath`, `dirPath`, `content`, `commandId`) рядом с полем `tool`.
* **Защита от циклов (`Loop Guard`)**: хранит сигнатуры выполненных шагов (`tool + arguments`) и прерывает выполнение при попытке повторить идентичное действие без прогресса.
* **Цикл самокоррекции (`Self-Correction`)**: если шаг завершился ошибкой (например, файл не найден `ENOENT`, неверный путь или неизвестный инструмент), исполнитель передаёт ошибку и контекст шага в `askModelToFixStep`, получает исправленный шаг от LLM (до `maxCorrectionsPerStep = 2` попыток) и продолжает выполнение плана.

### 4. Рекурсивная память и антипаттерны (`src/core/recursiveMind.js`)
* Сохраняет краткие слепки выполненных задач, ответов и сбоев в `mind/reflections/thought_<timestamp>_d<depth>.md` и обновляет стек последних 10 мыслей в `mind/state.json`.
* Ошибки и срабатывания `Loop Guard` автоматически маркируются как **`[АНТИПАТТЕРН / ОШИБКА]`** и подмешиваются в системный контекст последующих запросов, чтобы агент не повторял неудачные сценарии.
* Встроена автоматическая ротация файлов рефлексий (`MAX_REFLECTION_FILES = 30`), исключающая разрастание папки `mind/`.

### 5. Управление сессией LLM и GPU-мьютекс (`src/api/routes.js`, `src/core/mutex.js`, `src/core/contextPruner.js`)
* **Сериализация доступа к GPU**: `gpuMutex` гарантирует, что одновременные HTTP-запросы не вызовут гонку за контекст `node-llama-cpp` и не приведут к переполнению VRAM.
* **Контроль контекста**: `pruneMessages` ограничивает историю диалога (`DEFAULT_MAX_CONTEXT_MESSAGES = 12`, `DEFAULT_MAX_CHARS_PER_MESSAGE = 2000`), а сессия `LlamaChatSession` автоматически пересоздаётся при смене режима песочницы или достижении лимита ходов (`MAX_SESSION_TURNS = 10`).

## Инструменты агента (Tools Registry)

Все инструменты описаны в `src/tools/registry.js` и доступны планировщику в рамках разрешённой области видимости:

| Инструмент | Модуль | Аргументы | Назначение |
| :--- | :--- | :--- | :--- |
| `readFile` | `registry.js` | `{ "filePath": "..." }` | Чтение текстового содержимого файла с проверкой безопасности пути. |
| `writeFile` | `registry.js` | `{ "filePath": "...", "content": "..." }` | Создание или перезапись файла с автоматическим рекурсивным созданием родительских папок. |
| `deleteFile` | `registry.js` | `{ "filePath": "..." }` | Удаление файла в пределах разрешённой директории. |
| `listDir` | `registry.js` | `{ "dirPath": "." }` | Получение списка файлов и поддиректорий с указанием типа (`dir` / `file`). |
| `analyzeProject` | `projectScanner.js` | `{ "dirPath": "." }` | Рекурсивный аудит директории: число папок и файлов, общее количество строк кода, разбивка по расширениям, топ-5 крупных файлов и чтение метаданных `package.json`. |
| `generateUnitTest` | `registry.js` | `{ "sourcePath": "...", "outputPath": "..." }` | Статический разбор экспортов модуля (`function`, стрелочные `const`, `class`) и генерация заготовки unit-теста на встроенном `node:test`. |
| `runCommand` | `safeCommands.js` | `{ "commandId": "..." }` | Выполнение строго ограниченного набора диагностических команд из белого списка. |

### Белый список системных команд (`SAFE_COMMANDS`)
Вызов произвольных shell-строк заблокирован на уровне архитектуры. Инструмент `runCommand` использует `child_process.execFile` без запуска командной оболочки и принимает только идентификаторы из белого списка:

* `node-version` — вывод текущей версии Node.js (`process.version`).
* `npm-version` — вывод версии пакетного менеджера `npm -v`.
* `dir-list` — листинг файлов рабочей директории (`dir` на Windows / `ls -la` на Unix).
* `git-status` — краткий статус репозитория (`git status --short`).
* `git-diff` — сводка изменений в репозитории (`git diff --stat`).

## Модель безопасности и режимы работы

Агент поддерживает два режима работы, переключаемых как из веб-интерфейса (тумблер в шапке), так и через параметр `strictSandbox` в API:

1. **Строгий режим песочницы (`strictDefault: true`, включён по умолчанию)**
   * Все относительные пути автоматически изолируются внутри `tests/sandbox/`.
   * Попытки выхода за пределы песочницы (через `../`, абсолютные пути или указание корня проекта) отклоняются на уровне `resolveSafePath` (`src/tools/pathSecurity.js`) и на уровне системных инструкций модели.
2. **Свободный режим (`strictDefault: false`)**
   * Агенту разрешено работать с файлами во всей рабочей директории проекта (`WORKSPACE_ROOT`).
   * **Правило уточнения пути**: если пользователь в свободном режиме не указал конкретную директорию (например, написал *«создай файл config.json»*), агент обязан уточнить папку текстом и не создавать файл в корне проекта без подтверждения.
3. **Защита от Path Traversal и символических ссылок (`pathSecurity.js`)**
   * Проверка относительного смещения через `path.relative()`.
   * Разрешение реальных путей файловой системы через `fs.realpath()` и `fs.lstat()` для блокировки симлинков, указывающих за пределы разрешённой зоны.
   * Для ещё не существующих файлов выполняется обход вверх по дереву (`verifyNearestExistingAncestor`) до ближайшего существующего родительского каталога с проверкой его реального пути.
4. **Локальная привязка сети**
   * HTTP-сервер Express запускается строго на локальном интерфейсе `127.0.0.1`, исключая случайный доступ из внешней локальной сети.

## Установка и быстрый старт

### Требования
* **Node.js** версии `20.x` или новее (с поддержкой ES Modules и встроенного `node:test`).
* Локальная языковая модель в формате **GGUF** (по умолчанию ожидается `models/qwen2.5-7b-instruct-q4_k_m.gguf`).
* GPU с поддержкой Vulkan / CUDA / Metal (или работа в CPU-режиме средствами `node-llama-cpp`).

### Шаги запуска

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com/Eurodancer26/open-claw-local-agent.git
   cd open-claw-local-agent
   ```

2. **Установите зависимости:**
   ```bash
   npm install
   ```

3. **Разместите GGUF-модель:**
   Поместите файл `qwen2.5-7b-instruct-q4_k_m.gguf` в директорию `models/`.

4. **Запустите сервер:**
   ```bash
   npm start
   ```
   После запуска сервер будет доступен локально по адресу **`http://127.0.0.1:3000`**.

## HTTP и SSE API

### `POST /v1/chat/completions`
Основной OpenAI-совместимый эндпоинт для диалогов и запуска автономных планов.

**Параметры тела запроса (JSON):**
* `messages` *(Array, обязательный)* — массив сообщений формата `{ "role": "user" | "assistant" | "system", "content": "..." }`.
* `stream` *(Boolean, по умолчанию `false`)* — режим потоковой передачи ответа.
* `strictSandbox` *(Boolean, опционально)* — динамическое переключение режима песочницы (`true` — строгий режим, `false` — свободный режим).

**Пример запроса в режиме SSE-стриминга (`stream: true`):**
```bash
curl -X POST http://127.0.0.1:3000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [
      { "role": "user", "content": "Создай файл demo.js с функцией суммы и прочитай его" }
    ],
    "stream": true,
    "strictSandbox": true
  }'
```
В ответ сервер отдаёт поток `text/event-stream` с пошаговым прогрессом выполнения (`▶ Шаг 1...`, `✔ Успешно...`, отчётами о самокоррекции) и завершает сессию маркером `data: [DONE]`.

**Пример запроса в обычном JSON-режиме (`stream: false`):**
Возвращает стандартный объект `chat.completion`, дополненный полем `neural_routing` с оценками `NeuralSkillRouter` (`selectedSkill`, `confidence`, `isBroadOrMixed`, `topSkills`, `scores`).

### `GET /v1/mind`
Возвращает текущее состояние рекурсивной памяти агента из `mind/state.json` (`coreGoal`, `activeDirectory`, `mode`, `thoughtStack`).

## Трассировка и XML-отчётность

Модуль `ExecutionTracer` (`src/core/reporter.js`) автоматически протоколирует каждую сессию работы агента в структурированный XML-файл с экранированием спецсимволов и `CDATA`-секциями для фрагментов кода:

* `reports/chats/chat_report_<SESSION_ID>.xml` — полная трассировка диалогов и выполненных планов из веб-интерфейса или API.
* `reports/tests/test_report_<SESSION_ID>.xml` — трассировка тестовых прогонов при запуске `npm run test:llm`.

Каждый отчёт фиксирует режим работы, запрос пользователя, сырой план модели, список выполненных действий (`<actions>`), финальный ответ в чат и помиллисекундный лог событий (`<events>`).

## Roadmap (Этапы развития)

### Этап 1: Базовый фундамент и изоляция безопасности — Выполнено
* [x] Локальный Express-сервер с привязкой к `127.0.0.1` и веб-интерфейс с SSE-стримингом.
* [x] Интеграция `node-llama-cpp` и сериализация обращений к видеопамяти через `gpuMutex`.
* [x] Защита файловых операций (`resolveSafePath`, `fs.realpath`, проверка предков) и белый список команд `SAFE_COMMANDS` через `execFile`.

### Этап 2: Агентичный цикл Plan & Execute, Self-Correction и отчётность — Выполнено
* [x] Единый контракт для `stream: true` и `stream: false` с переключателем режимов песочницы.
* [x] Исполнитель планов (`executePlan`) с нормализацией шагов, `Loop Guard` и автоматической самокоррекцией при ошибках.
* [x] Персистентная память размышлений (`recursiveMind.js`) с фиксацией антипаттернов и ротацией файлов.
* [x] Генерация сводных XML-отчётов сессий (`ExecutionTracer`).

### Этап 3: Модульная архитектура, нейро-роутинг и расширенные инструменты — Выполнено
* [x] Декомпозиция монолитных модулей API и инструментов (`chatFormatter.js`, `contextPruner.js`, `planParser.js`, `pathSecurity.js`, `projectScanner.js`, `safeCommands.js`).
* [x] Рекурсивный нейро-роутер на CPU (`NeuralSkillRouter`) с поддержкой длинных составных промтов, динамическим сбросом инерции при смене темы и сохранением весов.
* [x] Расширение реестра инструментов до 7 утилит (`readFile`, `writeFile`, `deleteFile`, `listDir`, `analyzeProject`, `generateUnitTest`, `runCommand`).

### Этап 4: Дальнейшее развитие — В планах
* [ ] Добавление инструмента безопасного поиска по кодовой базе (`searchInFiles`) с ограничением выдачи.
* [ ] Автоматическое дообучение весов `NeuralSkillRouter` на основе подтверждённых успешных сессий из `reports/chats/`.
* [ ] Поддержка интерактивного подтверждения опасных действий (например, `deleteFile`) в свободном режиме через UI.
